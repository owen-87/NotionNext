# 正文输出与缓存修复实施记录

日期：2026-10-09。代码已在本地完成修复并通过生产模式验收，尚未部署到 funshow.top。

## 已实施的修改

1. `pages/_app.js` 静态引入并注册线上使用的 magzine 主题；`themes/theme.js` 在首次服务端渲染时直接取得真实布局。主题缺失时抛出错误，不再返回空布局。其他主题继续沿用原有加载方式。
2. Notion 正文在读取缓存、获取新数据时都检查根节点与嵌套内容块；同步块的内嵌内容也检查。数据库缺少结构、视图数据或查询中的文章元信息时停止生成。真实的空页面仍允许存在。
3. 删除“上游获取失败后返回空站点/无正文文章”的成功降级。生成失败会交给 Next.js；已有 ISR 页面保持上次成功版本，新页面不把失败结果包装成空的 200 页面。
4. 删除缓存时覆盖当前进程可用的 Redis、文件与内存存储。新增本进程的失效代次检查，防止删除之前开始的请求结束后重新写回过期缓存。
5. 全站刷新不再只清文件缓存、只刷新首页。现在清除本站的数据、配置、公告及旧/新版本正文缓存，然后依照站点地图逐页刷新首页、归档、分类和公开文章，包含多语言与旧的已移除公开路径。部分失败返回 HTTP 500 和 `failedPaths`，便于仅重试失败路径。不会清空共享 Redis 的其他数据。
6. magzine 分类目录补成实际的 `<a href>` 链接。真实没有公开文章的首页显示站点名称、说明和空列表提示，避免永久显示加载骨架。
7. 新增 `scripts/check-server-content.js`：只解析原始 HTTP HTML，不执行页面脚本，检查主体、H1、真实链接和文章正文，防止正文仅存在于 JSON 数据中却通过验收。

## 本地验收证据

本地缺少正式 `NOTION_PAGE_ID`，因此使用仓库自带的中英文公开模板数据库验收。下面的 38 个路径不是 GSC 中 funshow.top 的 33 个路径；不得将这些结果解释为线上已修复或 18 个 URL 已收录。

- 7 个相关测试套件，共 46 项通过：数据不完整、失败恢复、缓存失效期间的并发请求、多语言刷新、旧配置依赖清理、已移除页面、部分失败和接口鉴权等。
- 最终 `next build` 成功，50 个静态页面生成完成。
- `next lint` 通过；仓库已有的警告仍存在。
- 首页、归档、分类目录、分类文章列表和样本文章的原始 HTML 均有主体、H1 和实际链接。文章正文在不执行 JavaScript 时仍可读。
- 新启动的生产进程，未预生成的模板说明 UUID 路径首次请求为 `MISS`，正文主体 1628 个去空白字符、35 个实际链接；第二次为 `HIT`，内容一致。这里的字符数只用于比较稳定性，不是收录门槛。
- 在 `ENABLE_CACHE=true` 的本地单进程生产服务器上，`all:true` 成功刷新 38/38 个公开路径。随后抽查首页、归档、分类、分类文章列表、文章全部为 `HIT`，正文与链接稳定。
- 故障注入令样本文章的 Notion 请求返回 503：刷新接口返回 500 和该文章失败路径；排除脚本与样式后，旧文章 HTML 与失败前相同。撤除故障后再次刷新成功。
- 浏览器中分类项能进入文章列表，列表能进入文章，刷新后标题和正文正常，验收时未捕获浏览器错误。

第一次全站刷新曾在 `ENABLE_CACHE=false` 时触发 Notion 429 限流，因为每个页面重复获取全站数据。此次失败被如实报告，并没有存入空正文。启用数据缓存后的全站刷新通过。

## 上线前核对配置

确认正式部署项目仍使用 FunShow 的数据库 ID、域名和 magzine 主题。本地 `blog.config.js` 的数据库 ID 目前仍是模板值，未将它改成猜测值。

| 配置                                    | 核对要求                                                                           |
| --------------------------------------- | ---------------------------------------------------------------------------------- |
| `NOTION_PAGE_ID`                        | 使用 funshow.top 的真实数据库 ID                                                   |
| `NEXT_PUBLIC_THEME` / Notion 的 `THEME` | 最终主题为 `magzine`                                                               |
| `NEXT_PUBLIC_LINK`                      | `https://www.funshow.top`                                                          |
| `ENABLE_CACHE`                          | 批量刷新建议设为 `true`，减少重复获取数据库                                        |
| `REDIS_URL`                             | 若部署运行多个独立实例且需要全站数据立即一致，使用共享 Redis；凭据仅设置在部署平台 |
| `REVALIDATION_TOKEN`                    | 已有令牌保留，仅用于服务端鉴权，不能设为 `NEXT_PUBLIC_*`                           |

只清除某个进程的内存不能清除其他实例的内存。当前并发失效保护也只覆盖同一进程；多实例环境中的正在进行的写入、共享缓存失败、平台函数时限仍需按正式架构验收。本地没有 Redis 服务，本次未进行真实 Redis 多实例集成验收。没有共享数据缓存时，应通过重新部署更新构建产物，再按少量路径分批刷新及复核；不要据本地单进程结果宣称多实例已同步。

## 发布与复核步骤

1. 把本次修复发布到对应的正式部署项目，确认构建成功、域名指向该版本。保留正式数据库和环境配置。
2. 在管理终端中通过已有令牌刷新。令牌从本机环境读取，不能放进网址或公开输出：

   ```powershell
   $headers = @{ Authorization = "Bearer $env:REVALIDATION_TOKEN" }
   $result = Invoke-RestMethod `
     -Method Post `
     -Uri 'https://www.funshow.top/api/revalidate' `
     -Headers $headers `
     -ContentType 'application/json' `
     -Body '{"all":true}'
   $result
   ```

   如果响应部分失败，只对返回的 `failedPaths` 重试，并先查明是否存在上游限流、权限或数据不完整。路径批次最多 100 条；平台函数超时可能导致请求无法返回完整结果，此时改用小批次。

3. 在已安装本仓库开发依赖的工作目录中验收原始 HTML：

   ```powershell
   node scripts/check-server-content.js https://www.funshow.top
   node scripts/check-server-content.js https://www.funshow.top /article/1-1-2 /article/1-1-5 /article/1-1-10 /article/3-1-4 /article/2-1-3 /article/2-1-4
   ```

   默认检查首页、归档、分类目录、首个分类及首页样本文章；指定路径时仅检查这些路径。输出每页错误数组为空、退出码为 0 才算通过。再次请求比较缓存命中与内容；用浏览器直接打开、刷新和沿分类链接导航确认显示正常。

4. 按真实站点地图复核全部公开 URL，特别是此前正文不稳定的页面。确认 canonical、索引标签和状态码。完成后在 GSC 对少量重要文章运行实时测试、查看截图，再请求索引；不要把本地修复当作 Google 已收录。

## 官方行为依据

[Next.js ISR 文档](https://nextjs.org/docs/pages/guides/incremental-static-regeneration)说明，应以 `next build` 加 `next start` 检查生产缓存行为；生成时抛出异常，会继续提供上次成功生成的页面，并在之后重试。本文的故障验收实际验证了这一行为。
